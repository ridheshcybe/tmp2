AeroTwin is an AI-enabled, real-time digital twin for a four-cylinder aero piston engine: a physics simulator streams 10 Hz telemetry, an ML pipeline watches every byte for anomalies, classifies faults, scores an explainable health index, and predicts remaining useful life — before a human operator could ever notice a glitch.

01

Overview

Two systems, one engine, one SQLite database. Everything else in the workspace is support tooling.

🖥 Standalone frontend src/frontend

Plain HTML/JS pages served by serve.py on :8000. What run.bat opens. Talks to the backend through the same-origin proxy and a direct WebSocket — no build step, no framework.

Pages: dashboard (index.html), cutaway 3D simulator, telemetry charts, cylinder diagnostics, fault-injection lab, blackbox logs, phone controller.

⚙ SIH digital twin sih/

The engine room. Four packages:

  • simulator/ — physics telemetry generator + fault injection
  • ml/ — training + streaming inference pipeline (the AI)
  • backend/ — FastAPI REST + WebSocket on :8081
  • frontend/ — React cockpit (Vite) with the cutaway viewer

02

Architecture

The journey of one telemetry frame — physics to pixels in under 100 ms, ten times a second.

1
Physics step simulator/telemetry_gen/engine_model.py ISA atmosphere → RPM lag → fuel, CHT, EGT, oil, vibration, electrical sub-models, one tick at 10 Hz. fault_injection.py corrupts the healthy row (60 s ramp).
2
Tick loop backend/services/simulator.py asyncio loop: profile → (phase, throttle, altitude), apply overrides, step engine, build the frame, push to a 600-frame ring buffer, fire callbacks.
3
Process & store backend/routes/mission.py Frame → SQLite (buffered writes) → DigitalTwinService.process_frame().
4
One orchestrator, five analyses backend/services/digital_twin.py physics residuals → anomaly score + fault class → explainable health index → criticality + action → RUL + RTB alerts → sensor status assembly.
5
Broadcast backend/websocket_handler.py Full EngineState wrapped as TELEMETRY and fanned out to every WS client; dead sockets pruned.
6
Render src/frontend/aerotwin-api.js flatten() maps the rich state onto the pages: KPI cards with fluctuation chips + sparklines, phase chip, alert banner, and CUTAWAY_SET_RPM postMessage drives the 3D engine.

Why a physics baseline + tree ensembles (not an LSTM)?

The temporal signatures — trends, rolling variance, breaking correlations — are encoded explicitly in ~30 engineered features. Tree ensembles reach the same accuracy with ~100× less data, no GPU, and free explainability: every prediction can cite the residuals that drove it. The hybrid backbone means predicted = physics + ML correction.

⚙

Module-identity rule (a real bug's tombstone): all internal imports use the backend. prefix. Importing bare database silently creates a second module instance with its own DB handle — routes saw "Database not initialized" while init_db() "succeeded".

04

Flying the Engine

One control bar at the bottom of the canvas runs everything: presets, flight transport, manual throttle, and the phone. The engine visibly spools toward every command — it never snaps.

🎚 ENGINE — presets

Idle 1.2K / Cruise 2.4K / Takeoff 5.8K. One click commands a throttle (rpm / 3600) to the backend; the session auto-starts if no mission is running. The cutaway spools to the commanded rate through its speed model.

🛫 FLIGHT — transport

Test Flight flies the compressed profile — idle → takeoff → climb → cruise → descent → landing in ~2.5 min — with the phase chip tracking each stage. Abort spools back down to idle instead of leaving you mid-air. To Idle releases manual control to ground idle.

🎮 MANUAL — the stick

Drag the throttle and the engine reacts live. A MANUAL chip shows when the stick is in command; the 5 % floor means the engine idles rather than dies. Every fluctuation shows on the KPI cards: ▲/▼ delta chips (1-second windows) and live sparklines under each value.

📱 PHONE — scan & fly

Pair phone shows a QR. Scanning it auto-pairs (camera + WebRTC handshake, nothing typed) and the phone becomes a live controller: throttle lever, presets, flight start/abort, release — with phase, RPM and throttle echoed back so the display stays live. Commands ride the WebRTC data channel with a REST fallback through serve.py's /__ctl queue.

Safety behaviors worth knowing

  • Overspeed protection — if commanded RPM ≥ 6400 or RTB_CRITICAL, the cutaway HUD goes red and cuts the commanded throttle to fast idle until it clears.
  • Burst warning — anomaly score ≥ 0.55 turns the HUD amber: "ABOUT TO BURST".
  • Hand-crank — grab the crankshaft, a piston, a rod or the propeller and drag: the whole slider-crank hierarchy answers, then friction coasts back to the commanded throttle.
  • Fresh missions forget — starting a mission resets the health-index EMA, so a new flight never inherits the previous one's degraded score.
⚠

Manual + mission interplay: starting a Test Flight replaces a running manual session (the simulator rewires, it doesn't refuse). Releasing the stick in a manual session parks at ground idle; releasing inside a real mission hands control back to the profile.

05

API Reference

Base URL http://localhost:8081 — or same-origin :8000/api/... through the proxy. JSON everywhere; ISO-8601 UTC timestamps; uniform errors {error, detail, status_code}. Full request/response schemas live in API_REFERENCE.md.

System

GET/healthliveness + components
Component status: ml_models (loaded / fallback / error), simulator (running / idle), websocket_clients, uptime. Used by run.bat's health-wait and the dashboard's Force Sync.

Engine — the rich read

GET/api/engine/{id}/statethe single richest read · WS payload
Full EngineState: observed frame, physics expected + residuals, health index (category, trend, confidence, contributors, explanation), anomaly score, fault class/severity/criticality/action, RUL + RTB alerts, sensor status, alerts. Cached per frame — polling between ticks is free. 503 when no mission is running.
GET/api/engine/{id}/telemetry?limit=100ring buffer, max 600
Last N raw frames from the simulator's in-memory buffer (60 s @ 10 Hz). Empty list, not 404, before any frames exist.
GET/api/engine/{id}/health · /faults · /rulslices of state
Single-concern slices of /state for cheap polling.

Missions

POST/api/missions/startprofile: default | test_flight | manual
Body: {engine_id?, duration_s=600, ambient_offset_c=0, name?, profile}. Creates the DB row, starts the tick loop, pipes frames through ML → SQLite → WS. Resets the health EMA. Only one simulator exists; starting while running re-wires the callback.
POST/api/missions/{id}/stopflush + COMPLETED
Stops the sim, flushes buffered telemetry, stamps ended_at. Unknown id → 404; already-stopped → no-op returning the stored status.
GET/api/missions?limit=50 · /{id} · /{id}/summaryhistory + aggregates
Newest-first list; per-mission stats (avg/min health, anomaly count, fault distribution, min RUL); the full report shape.

Fault injection

POST/api/faults/inject8 classes · 60 s ramp
Body: {fault_type, severity=0.7, target_sensor?} — HEALTHY, INJECTOR_DEGRADATION, MISFIRE, LUBRICATION_FAILURE, OVERHEATING, SENSOR_DRIFT, SENSOR_DROPOUT, ABNORMAL_VIBRATION, ALTERNATOR_DEGRADATION. Effects ramp in over 60 s; audit row written; FAULT_INJECTED broadcast. 400 if no mission is running.
POST/api/faults/clearand GET /api/faults/types
Clear removes all active faults (broadcasts FAULTS_CLEARED). Types returns the 8 faultable classes with criticality + recommended maintenance action.

Simulation controls — the interactive stick

POST/api/simulation/throttleauto-starts a session
Body {throttle: 0.0–1.0}. Overrides the profile from the next tick. No mission running? It auto-starts an interactive manual session — this is why the slider and phone work the instant a page opens. Response: {throttle, status:"set", mission_id, auto_started}.
POST/api/simulation/throttle/releasehand back the stick
Drops the interactive override. In a manual session the engine parks at ground idle; in a real mission the profile takes over. 400 if not running.
GET/api/simulation/status+ POST /altitude
{is_running, mission_id, frame_id, sim_time_s, hz, active_faults, phase, profile, throttle, throttle_manual}. Altitude override (0–45 000 ft) mirrors throttle, including auto-start.

Reports & replay

GET/api/reports/{id}+ /download · /health-timeline
Post-mission analysis: executive summary, health timeline (≤500 downsampled), anomaly events, fault predictions, RUL timeline, priority-ordered maintenance advisories, sensor + environmental summaries. Download sends it as an attachment; health-timeline gives the untruncated series for charts.
POST/api/replay/startspeed 0.1–10×
Loads a stored mission for replay; frames then stream over the WebSocket at speed. HTTP fallback: GET /api/replay/frames/{id}?start_s=&end_s=&limit=5000.

WebSocket WS ws://localhost:8081/ws/telemetry/{engine_id}

08

AI & ML

Everything "AI-enabled" means. Four scikit-learn models on top of an analytic physics backbone, wrapped in an explainable health index. Deep detail in ML_MODELS.md.

Layer 1 — physics baseline (not trained)

ml/physics_baseline.py computes the expected healthy value of every sensor from the operating point — mirroring the simulator's own calibration, so a healthy engine produces residuals ≈ 0. The compact 10-vector (r_cht_avg/max, r_egt_avg/max, r_fuel, r_oil_p, r_oil_t, r_vib, r_batt, r_alt) feeds everything downstream. Deterministic, explainable ("EGT is +76 °C above physics"), robust to dataset shift.

Layer 2 — streaming features (~30, strictly causal)

Same code path for training and inference — no train/serve skew. Conditions + one-hot phase, raw channels, the 10 residuals, 60 s rolling stats, 180 s trend slopes (faults are trends, not jumps), and coupling correlations (corr_oilp_rpm, corr_egt_cht…) that break characteristically under faults.

Layer 3 — the four models

#ModelAlgorithmKey outputs
1Anomaly detectorIsolation Forest, healthy-only traininganomaly_score 0–100, is_anomaly (threshold fit on validation at the 95th percentile)
2Fault classifierRandom Forest, 9 classesfault_class + confidence (max class probability)
3Degradation severityRF regressor → [0,1]severity; per-tree spread doubles as confidence
4RUL regressorRF on log(minutes)rul_min + 68 % interval rul_lo/hi, confidence

Layer 4 — the explainable Engine Health Index

formula 
EHI = 100 × (1 − Σ wᵢ · penaltyᵢ)

residual     w = 0.25   worst |z| of physics residuals (÷ 8.0σ ⇒ full penalty)
anomaly      w = 0.20   anomaly_score / 100
fault        w = 0.25   P(class) × criticality(class)
degradation  w = 0.20   severity from model 3
sensor       w = 0.10   fraction of missing/frozen sensors
  • Smoothing: EMA with cadence-adaptive τ ≈ 60 s + hard rate limit ±15 pts/s — 10 Hz live and 1 Hz replay behave identically.
  • Weight redistribution: a missing model's weight is redistributed, never silently dropped.
  • Data-quality gate: below 60 % valid sensors the index goes stale, capped at 50.
  • Explanations: engineer-readable — "EGT residual (max cyl) +76 °C (4.2σ above healthy baseline)".

The fallback chain

A
Trained bundle present? ml/inference.pyInferencePipeline — 4 models + feature impacts + recommended action.
B
FallbackAnalyzerPhysics-residual z-score rules: r_oil_p < −2.5 → LUBRICATION_FAILURE, r_cht_avg > 2.5 → OVERHEATING, and so on. Honest low_confidence: true.
C
Ultra-minimal heuristicVibration/RPM score at confidence 0.3. The API never breaks — /health reports which level is active.

09

Simulator Physics

The ground-truth world: a ~100–130 hp air-cooled, horizontally-opposed 4-cylinder aero piston (the MALE-UAV class). Full constants in SIMULATOR.md.

⚠

Honesty note (from the source): these are simulation equations calibrated to land inside realistic sensor envelopes — not certified engine equations. They exist to make the twin behave credibly and give residual-based detection a meaningful baseline. The only randomness is the seeded default_rng(42).

Sub-models, one step per tick

Sub-modelShapeCalibration
ISA atmospherelapse rates → temp, pressure, density ratiostandard
RPM dynamicsfirst-order lag toward throttle × density target1100→5600 rpm · τ 1.0 s
Fuel flowpower law on effective throttle1.1 + 13.8·t^1.3 L/h
CHT / EGTNewton cooling per cylinder; EGT fast + altitude-leanτ 45 s / τ 2 s
Oil temp / pressureslow integrator; pump ∝ RPM, viscosity ∝ Tτ 400 s · 265 kPa base
VibrationRMS baseline ∝ RPM + load—
Electricalbus charges above ~1500 rpm14.25 V vs 12.55 V
Injection timingRPM advance + CHT retard, clamped18–38°

Per-cylinder ±15 °C EGT spread is deliberate manufacturing variation on an otherwise cylinder-symmetric baseline — a learnable, documented pattern, not noise.

LUBRICATION_FAILUREoil pressure ↓ accelerating · oil temp ↑ · CHT/EGT ↑1.00

aerotwin-api.js — one client, three modes

Connection ladder WS → REST poll → demo generator, mode always visible in the header chip. flatten() maps the rich EngineState onto page-friendly frames. Command surface: setThrottle/releaseThrottle/setAltitude, injectFault/clearFaults/faultTypes, startMission/stopMission, missions/mission/missionSummary, healthTimeline/report, simStatus/health. Offline, demoFrame() synthesises a plausible cruise frame (honestly labelled DEMO).

serve.py — more than a static server

  • REST proxy — /api/* + /health → 127.0.0.1:8081; clean 503 JSON when the backend is down (this is why pages never hit CORS).
  • LAN IP endpoint — GET /__lanip so pages can build the pairing QR (a browser can't see the host's LAN IP).
  • Pairing relay — POST /__pair, GET /__pair/{t}, POST /__pair/{t}/answer (one-time tokens, 15 min TTL).
  • Command relay — POST /__ctl + GET /__ctl?since=: the phone's REST fallback channel.
  • HTTPS on :8443 — self-signed cert via openssl; phones refuse camera access over plain HTTP.
